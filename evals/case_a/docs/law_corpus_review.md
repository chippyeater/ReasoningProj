## 纳入 4 条而非盲目追加所有条款

第63条：违约损失中的可预见性、避免扩大损失、获得额外利益以及减少支出等计算因素。与本案房屋空置和重新出租的讨论直接相关，但不单独证明具体损失金额。

第64条：以抗辩或反诉提出调整违约金的程序及举证问题；本案只有在押金不退约定具有违约金性质等前提下才相关。

第65条：违约金明显过高时的衡量因素及一般30%标准；不能套用成押金必返70%、只赔3天房租的自动公式。恶意违约的限制也需要审查事实。

第67条：没有约定定金性质的押金不能直接适用定金罚则；这是本案“押金”性质的强关联条文，也直接补齐原 L006 仅靠第586条容易误判的漏洞。

第61条（正式稿）涉及持续性定期合同中不支付价款、租金等金钱债务而请求解除合同等条件；目前案卷描述“提前搬离”，没有明确租金拖欠事实，因此**未**作为核心候选纳入。注意公开征求意见稿和正式稿的第61条、第64条、第65条编号与内容不相同；一律使用2023年正式文本。

## 运行时法规库被校正的历史问题

原 `backend/data/laws.json` 有第584条非逐字改写、第707条误用第703条定义、第714条错误写成提前退租责任、第93条误写成电子数据范围（实际为第14条内容）、第466条错误混入格式条款解释等问题。本次直接从已核实的官方法条重新生成运行库，保留其运行所需 `doc_type`、`keywords`、`effective_status`，更正内容，并统一运行时和 Gold 的法条 ID。运行库中额外保留的第465、466、509条与证据规定第93条，均核对原文。

法条 ID 变更是有意进行的数据迁移：原 `law_1..law_8` 不能继续作为 Gold ID 使用，新运行库采用 `LAW-*` ID，若数据库中已有以旧法条 ID 持久化的结果，必须单独迁移或重新检索。不要仅根据旧条号生成迁移映射，因为旧条号存在错误配对。
