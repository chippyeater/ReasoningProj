# 案件 A v1.2：关键节点 Gold 人工复核

## 已实施的压缩

- 从 37 条预标注缩减至 **16 条需要独立显示和评价的关键元信息**；删除的是 Gold 节点要求，并非原文件内容。
- 以 `docs/legacy_id_migration.json` 保留每条旧 ID 的处理结论和映射；以 `docs/merged_source_audit.json` 审核多段来源是否真实、是否同一方重复。
- 核心信息包括：两位当事人、合同租期和租金、押金金额、合同押金条款、支付文字记录、退租与协商经过、接租说法、双方押金及损失立场。
- 张某“接续租客入住”和李某“空置数日”没有被强制标为直接矛盾；空置与经济损失没有被当作同一命题。

## 需要人工复核的合并边界

1. **U004** 将合同租期和租金放在一张「合同租赁条件」节点，租金用于损失背景，不强制额外建金额节点。
2. **U008** 将两个押金处理条款置于一张节点，但不宣称条款有效。
3. **U015** 李某的 2月25日条件式协商和 3月1日“到时看情况”同节点，保留两段精确原文，不能写成已达成部分退款协议。
4. **U016** 张某本人在聊天和笔录的三段表述同节点，这不是三份独立证明。
5. **U019** 李某多次拒退及解释同节点，`stance_target` 保留争点归属。
6. **U022** 3月5日聊天“这周搬走了”不能单独证明在 3月5日搬离；3月5日精确日期来自张某笔录。
7. **U026** 张某所称新租客入住与另签合同归在接续租住节点，两个事实分别保留原文，但都未经独立佐证。
8. **U035** 3月5日李某称当时空着与后来声称空了几天合并，但不能推论此后持续空置。

## 去重标注规则

1. 先判断独立推理必要性，再提取；不按对话轮数或笔录句数决定节点数。
2. 同一方对同一语义的重复陈述可以合并，被合并的重要原发言日期与来源逐条保存在 `source_refs`；没有独立推理价值的聊天追问仍能从原文按需查阅。
3. 合并同一方多处来源 **不会提高事实可信度或算作独立交叉印证**。
4. 不同人之间的实质对立及合同约定与付款记录必须各自独立；主张本身不能作为事实确证。
5. 数字、时间优先写入核心事件与合同条件，不强制单独建状态节点。
6. 删除测试：若不影响争点、时间线、支持/反对与缺失信息判断，也无独立可引用价值，则不要求成为节点。
7. 不能被抽成节点的文字仍在 `fixtures/parsed/`，可按需引用，用户不丢失原文。

## 评测及限制

- 16 条是**案件 A 的建议关键结构**，不是其他案件必须遵循的数量限制。
- `gold_relations.jsonl` 关系由语义重审重建，不能用旧关系逐条机械换 ID。
- `gold_view_cases.jsonl` 中信息 ID、分组和关键时间线已重编；仍为参考而非唯一正确布局。
- 去掉聊天文件时，张某/李某笔录仍能支持部分合并节点；不能把这些节点整体设为禁出，只能禁止引用已移除聊天。
- 仍需检查原始 DOCX 的一致性、人工法律解释与合并粒度。
