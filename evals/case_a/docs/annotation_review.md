# 案件 A｜任务型 InfoUnit 标注与人工复核（Gold v1.7）

## 标注目标

核心争点：**提前退租后押金是否应退还**。相关争点为实际经济损失及双方是否协商改变押金安排。

当前 Gold 共 **17 条最小有用推理单元**。节点是为用户理解案件、比较双方立场、检验证据和生成推理视图服务的，不是每句话、每个时间点或每个语义子句都要拆成卡片。具体数量不是模型输出上限。

## 节点组织原则

1. **有用性优先**：新增节点须能独立帮助理解争点、核查事实、对比立场或寻找证据；没有推理价值的聊天寒暄和宽泛回应可省略。
2. **相关内容可以成组**：同一合同内的互斥押金返还条件（U008）、出租人的整体拒退立场（U019）、多份材料对空置期间的不同表述（U035）均保留一个节点；各子条件和来源不能丢失。
3. **有不同核查任务才拆分**：张某称3月8日有人入住（U026）与称新租客后来另签合同（U027）要查验的原始证据不同，故分别建节点；签约具体日期未知，不可补写。
4. **不逐句提取**：U015 保留2月25日有条件协商退部分押金的提议；3月1日“到时候看情况再说”没有新确定处理规则，不列为Gold必要内容，也不能反推已经达成协议。
5. **主张与事实判断分开**：U029 对实际损失的判断与 U030 不应全扣押金的处理立场分别关联不同争点，可分别受到支持/反对。
6. **来源与真假分离**：U016 所称已找到接租者在聊天和笔录中重复，不是两份独立证实的证据；U022 的聊天时间较模糊，笔录给出具体搬离日；U035 的即时空置与数日空置不等于已经核定空置天数。
7. **合同条件成组**：U004 租期及月租作为租赁背景条件保留一张卡；U006 是合同约定押金2000元，U010 是转账记录载明支付2000元，必须区分约定与实际支付。

Gold的 content 主要陈述材料支持的信息及必要的不确定性；标注者的方法说明、为什么拆分、法律效力分析放在本文件，不要求模型重复解释标注逻辑。

## 关系与视图评测

- U029 与 U036 代表对损失的不同说法，U030 与 U019 代表对押金处理的相反立场，不能将其融合成同一方观点。
- U035 空置可能与 U036 声称的经济损失相关，但不能据此算出损失数额或认定全部押金应当扣除。U035→U036 的 support 不作为必须有或必须没有的关系。
- U026 与 U027 是两种需要不同证明材料的事实。展示整体损失评估时可共同呈现，但不能把“另签合同”塞回 U026 的内容。
- 时间线中的未知合同签订日期保持未知。不得把“后来”转换为未经材料记载的具体签署日。
- 生成式视图例子只指定有用的组织方向，不是唯一正确界面布局；不要求展示3月1日“看情况”这句话作为独立内容。

## 评分说明

`gold_info_units.jsonl` 的17条Gold用于覆盖对照；`score_predictions.py` 的一对一匹配是**诊断性指标**。评测报告还需说明：核心争点是否可理解、重要证据/关键条件是否完整、哪些节点有误合并或不必要拆分、各方发言与证据来源是否可核查。不得因模型多提取一个不重要句子而当作提高覆盖，也不得仅根据预测条数判断优劣。

该标注方案由项目设计者定义，法律适用、内容真实性及推理结论仍需人工复核。

## v1.7 对齐与拆并复核

- 先对照正式 Gold 的必要信息、条件和来源归属审核语义是否完整，不要求照抄措辞，也不重新设计 Gold。U015 不再要求后续模糊回复；U016 不要求另建“愿意帮忙找人”节点。
- U008、U019、U035 的组合本身不构成误合并；若遗漏适用条件、混淆来源时点或把整体立场写成已认定事实，应分别记录完整性或来源错误。
- U026（入住）/U027（另签合同）、U029（损失判断）/U030（押金处理诉求）具有不同核查或判断用途。同一预测囊括两项时最多计一项；另一项可在人工报告中标为“内容出现但独立信息误合并”，不能作为第二个命中。
- “内容出现但误合并”不是所有复合句的通用标签。须列出预测 ID、相关 Gold ID、独立推理用途及来源，不把日期、句数、分类差异本身当作拆分依据。合法综合节点、真正遗漏和部分内容不足应分开报告。
- 只能比较以同一 Gold 版本和哈希重新复核得到的评分。`results/` 内既有旧版命中及拆分统计保留为历史记录；其版本依据见 `historical_evaluation_index.json`。本轮依赖审计不重做历史语义评测。
