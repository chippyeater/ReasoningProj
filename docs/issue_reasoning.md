# Issue 协作推理 MVP

实现依据为用户任务 `tasks/10231658.md`。可勾选验收清单只保留本地 `tasks/10231658-checklist.md`，不纳入 Git。

## 使用闭环

在 Issue 画布右键“新建假设”，保存内容、证据判断（未证实/已证实/已证伪）与工作状态（活跃/已弃用）。弃用只降低视觉优先级，可以恢复。节点“查看与编辑”或右键进入编辑器。

从假设编辑器或右键“关联已有证据”，选择全案 InfoUnit，填写支持/反对/待核实语义与理由。支持为绿色实线，反对为红色虚线，待核实为灰色虚线；点击连线可修改或解除。来源原文在关联编辑器按需展开，可定位原信息。人工/Agent 建议已采纳的来源独立于关联语义，用户修改保留来源并标明人工修正。

“新建证据缺口”或假设中的“添加证据缺口”支持关联多个假设、可选已有信息和未解决/已解决状态。缺口是问题，不是虚构的材料。正式节点复用当前画布选择、拖动、缩放、坐标与 Issue 恢复机制；新节点寻找空位，不重排已有节点。

保存用户修正后可“请 Agent 检查”，从现有灵动岛发送。Agent 继续按需调用同一组三个只读工具，可返回普通调查答案和可选建议；事实查询不强制生成建议。候选以半透明卡片预览，灵动岛可查看依据、采纳或忽略。采纳前不写正式推理数据，忽略只丢弃本次预览。刷新/切换不保留候选或对话历史。

## 数据与接口

沿用 `issue_workspaces.json`，每个 Issue 增加默认空的 `reasoning`：

- `hypotheses`：稳定 ID、内容、判断、工作状态、修订号、最近修改时间/来源、可选采纳凭据。
- `gaps`：稳定 ID、问题、关联假设 IDs、可选 InfoUnit IDs、解决状态和修订元数据。
- `links`：稳定 ID、InfoUnit 与 Hypothesis IDs、语义、理由、人工/Agent 来源及最近修改者。
- `accepted_proposals`：服务端运行与建议索引到正式对象的幂等映射。

所属 Issue 由工作区父键确定。业务 InfoUnits、Relations、SourceRefs 不复制、不修改；`HypothesisView` 等既有生成式视图不承担这些可编辑工作对象。旧文件缺少 `reasoning` 时读作空集合，旧坐标与字段保留。引用了某个 InfoUnit 的正式推理关联/缺口会阻止删除该共享信息，避免断开引用。

`PATCH /api/cases/{case_id}/issue-reasoning` 每次接受一个人工操作：`hypothesis`、`gap`、`link` 或 `unlink_id`，绑定 `issue`，可附新节点 `position`。后端分配 ID、修订号和来源，校验所有引用、当前 Issue 归属及重复关联，并通过现有原子 JSON 写入统一保存。

`POST /api/cases/{case_id}/reasoning-proposals/accept` 仅接受 `issue/run_id/proposal_index/position`，不接受客户端重新编写建议或证据。后端读取该案件成功调查审计中的已校验建议，核对 Issue、证据内容摘要和目标假设修订号，再原子写入正式对象、画布和幂等映射。重复采纳返回已有对象；证据/用户推理改变后旧建议返回冲突，不覆盖用户。修改关联或缺口也会推进相关假设修订号，保守地使旧建议过期。

## Agent 边界

兼容扩展调查结果 `proposals`，旧结果省略时按空集合处理。实际模型严格 Schema 要求该字段，可返回 `[]`。支持新假设、证据关联、缺口和判断调整四种建议；新假设采纳后仍为未证实、活跃。引用须属于本轮实际取回的顶层 InfoUnits/SourceRefs；原文索引仍经调查循环校验。

`hypothesis_ids` 保留引用有限工作上下文已有假设的方式。仅 Evidence Gap 可额外填写 `hypothesis_proposal_indices`，指向同次运行 `proposals` 原始数组中的新 Hypothesis 建议，索引从 0 开始；两个列表至少一个非空，合计最多 5 个目标。旧结果缺少此字段时按 `[]` 读取，其他建议该字段必须为空。模型严格 Schema 通过 `anyOf` 前置建议类型、字段组合、目标非空及索引范围约束；目标类型、实际数组长度、重复目标和合计数量仍由后端校验。

索引与外层 `run_id` 共同定位，不能引用其他运行；校验、API 返回、前端筛选和采纳不排序、不重新编号。采纳从该运行的成功审计重新核对目标种类及运行归属，要求目标假设已由用户采纳，并通过 `accepted_proposals[run_id:index]` 找到真实 ID。未采纳时明确拒绝，不自动连带采纳或猜测关联。父假设材料变化、人工修正或其他推理变化使旧缺口过期；同轮已采纳的关联缺口造成的修订递增允许继续采纳其余同轮缺口。正式工作区结构不增加字段，审计不被改写。

请求可传最多 3 个 `selected_reasoning_ids`。上下文优先显式选择、其关联缺口、目标关键词与最新修改，最多 3 个工作对象候选、3 个相关假设和 5 条关联；内容摘要最多 300 字、理由最多 160 字，显式标记是否仍有省略。内容、判断、弃用状态和修订号来自最新用户保存值，不注入完整画布/全部推理/历史对话；其中引用的 InfoUnit IDs 不等于已读证据，仍需按需工具读取。Issue 状态仍完全由用户控制。

所有模型输入、工具返回及最终建议沿用现有审计与 Langfuse 机制。错误按 JSON 解析、结构、Proposal 语义及引用分类记录字段路径和错误码；即使追踪不采集内容，也保留不含案件文本的错误位置及类别。调查阶段只写独立运行审计；正式工作区只能由人工编辑或明确采纳接口写入。

## 离线验收

沿用 `docs/investigation_agent.md` 中的隔离后端和 Vite 启动方法。后端：`test_reasoning_workspace.py`、`test_reasoning_proposals.py`。可见浏览器：`frontend/tests/reasoning-workspace-smoke.cjs`，只模拟模型边界，真实运行 API、循环、审计与持久化；其他四组浏览器脚本验证已有功能。

尚未验证付费真实模型的建议质量。引用可定位不能证明其充分支持判断；采纳是用户决定，不代表独立核实。不提供多人冲突合并、通用审批/撤销历史、自动收集外部证据、生成布局或通用建议依赖图；仅允许上述同轮 Gap 到新 Hypothesis 的引用。新的证据关系需要进一步检验，不能由片段或引用次数推导独立证据数量。
